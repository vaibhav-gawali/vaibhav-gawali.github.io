# AGENTS.md

This repository is a Jekyll site using the **Chirpy** theme.

## What to build / preview locally

1. Install dependencies (Ruby gems)
- `bundle install`

2. Build the site
- `bundle exec jekyll build --config _config.yml`

3. Preview
- `python3 -m http.server 4000 --directory _site`
- Open: http://127.0.0.1:4000/

(If you preview from a custom destination folder, point the server’s `--directory` to that folder.)

## Content model and where to edit

1. Posts
- Directory: `_posts/`
- Posts are Markdown files with YAML front matter.
- Key fields used by Chirpy/archive pages:
  - `title`
  - `date`
  - `categories` (optional)
  - `tags` (optional)

2. Chirpy navigation tabs (sidebar)
- Directory: `_tabs/`
- Each tab is a Markdown file.
- Must have `layout` and `permalink`.
- Tab ordering is controlled via `order`.

Current required tabs:
- `_tabs/home.md` → `/`
- `_tabs/about.md` → `/about/`
- `_tabs/contact.md` → `/contact/`

Important: Avoid creating duplicate “home” definitions.

3. Social icons in the sidebar bottom
- Configured by: `_data/contact.yml`
- Chirpy renders social links/icons from this data file.

4. Tag archives
- Tag pages are generated by `jekyll-archives`.
- Ensure `jekyll-archives` is configured in `_config.yml` with `enabled: [tags, categories]`.

## Chirpy runtime assets

Chirpy’s Home page feed relies on JavaScript bundles.

- Ensure `assets/js/dist/` exists and includes at least:
  - `home.min.js`
  - `theme.min.js`

If you run into a blank home middle / missing post list:
- First check `assets/js/dist/home.min.js` is present in the build output.
- Then re-check that the Home page is served using the Chirpy `home` layout.

## Common pitfalls (known to matter in this repo)

1. Home page conflicts
- Do not keep multiple competing “home” sources (for example, both `index.md` and a tabs/home file with conflicting layouts).

2. Duplicate sidebar entries
- Sidebar tabs are driven by the Jekyll `tabs` collection.
- If you see duplicates, verify:
  - `_config.yml` has a `collections: tabs:` registration
  - Only one tab maps to `/`.

3. Links not clickable
- If you place raw URLs, Markdown rendering may not convert them into links reliably.
- Prefer explicit Markdown links or HTML `<a>` elements.

## Temporary files / output locations

- All temporary build/test artifacts MUST be generated under `.tmp/` at the repository root.
- Do not generate temporary outputs in the repo root or commit them.
- Example usage: build into `.tmp/<your-folder>/` and serve from there.

## Pull request / change expectations

- Keep changes minimal and focused on the requested pages/posts/tabs.
- After any structural change to `_config.yml`, `_tabs/`, or archives, rebuild and confirm routes:
  - `/`
  - `/about/`
  - `/contact/`
  - `/tags/<tag>/` (example: `/tags/testing/`)
